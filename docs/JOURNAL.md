## 2026-11-03 — Мышь: указатель без ускорения и скорость (ветка `feature/mouse-scroll`)

**Как это делает LinearMouse (изучен исходник, код не копировали).** С событиями движения он ничего не делает, а меняет свойства
HID-службы мыши через `IOHIDServiceClientSetProperty`: «без ускорения» — `HIDUseLinearScalingMouseAcceleration = 1`, если у мыши
есть такое свойство, иначе `HIDMouseAcceleration = −1`; скорость — `HIDPointerResolution` (меньше — быстрее), после него ускорение
записывается ещё раз. Свойства не сохраняются: при переподключении мыши они сбрасываются, поэтому их надо ставить заново.
В конфиге пользователя указатель был настроен только у первой M240 (`speed 0.0809`), у подключённой LOGI M240 B — нет.

**Что на macOS 27.2.**
- `HIDMouseAcceleration` у M240 B было 0,5 (= `com.apple.mouse.scaling`, ползунок «Скорость перемещения»). `hidutil property --set`
  со значением −65536 (−1 в IOFixed) работает без sudo, в реестре виден `HIDMouseAcceleration = −1`. Пользователь попробовал: «то, что нужно».
- В системе уже стоит `com.apple.mouse.linear = 1`, а в `HIDEventServiceProperties` — `HIDUseLinearScalingMouseAcceleration = 1`,
  но со службы мыши свойство читается как null, и ускорение у пользователя при этом было. Поэтому используем −1.
- Мышь и тачпад различаются по `HIDPointerAccelerationType`: `HIDMouseAcceleration` у M240 B, `HIDTrackpadAcceleration` у встроенного тачпада.
- `HIDPointerResolution` у M240 B (служба `AppleUserHIDEventService`, DriverKit) со службы читается как null; в реестре — 26214400 (400 dpi).
  Запись 200 dpi через `hidutil` и через приложение отчёт «успешно» даёт, но в реестре остаётся 400. Влияет ли это на скорость
  курсора — **не проверено**, нужна живая проверка ползунка.

**Что сделано.**
- Таргет `PointerMath` (без зависимостей от системы): по настройкам, системному ускорению и исходному разрешению мыши — целевые
  ускорение (−1 или системное) и разрешение (исходное / множитель, в пределах 10–1995). Тесты `PointerMathTests` — 5.
- `MousePointer.swift`: `IOHIDEventSystemClientCreateSimpleClient`, службы мышей (GenericDesktop/Mouse и тип ускорения мыши),
  раз в 2 с сверяет значения и ставит заново — так подхватываются переподключение мыши и сдвиг ползунка в Системных настройках.
  Пока обе настройки по умолчанию, мыши не трогаются вовсе, в том числе при запуске. При выходе из приложения возвращаются
  системные значения. Записанное разрешение запоминается, раз его нельзя прочитать, иначе оно переписывалось бы каждые 2 с.
- Модуль «Мышь», раздел «Указатель мыши»: «Без ускорения (как в Windows)», «Скорость указателя» ×0,3–×3,0, список мышей,
  «Сбросить к системным».

**Проверено.** `swift test` — все тесты проходят. Сборка без ошибок, подпись «Mac Tweaks Dev». Запуск с настройками по умолчанию
мышь не меняет (ускорение осталось 0,5). Переключатель в интерфейсе ставит M240 B ускорение −1, тачпад не затронут.
Скорость ×2,0 из настроек при запуске записывается, но в реестре не видна (см. выше).

**Не проверено.** Меняет ли ползунок скорость на ощупь. Повторное применение после переподключения мыши и сна.

## 2026-11-03 — Мышь: обращение колеса и прокрутка по строкам (ветка `feature/mouse-scroll`)

**Задача.** Повторить две функции LinearMouse (у пользователя мыши LOGI M240 и OMR310, в его конфиге: `reverse.vertical = true`,
`distance.vertical = 3`): колесо мыши крутит в обратную сторону, а тачпад остаётся с «естественной» прокруткой;
каждый щелчок колеса прокручивает фиксированное число строк, без ускорения. Код LinearMouse (GPL-3.0) не копировали.

**Что сделано.**
- `EventTap.swift`: общий `EventTap` (создание tap в главном run loop, повторное включение после `tapDisabledByTimeout/UserInput`,
  слежение за разрешением раз в 2 с: выдали — tap создаётся без перезапуска, отозвали — снимается) и `EventTapPermission`
  (`.inputMonitoring`: `CGPreflightListenEventAccess`; `.accessibility`: `AXIsProcessTrusted`; запрос и ссылка на нужную панель
  Системных настроек). `LayoutSwitcher` переведён на него, своего кода tap больше нет. `RunningApps` — общий наблюдатель
  запущенных приложений для предупреждений о CommandShift и LinearMouse.
- Таргет `ScrollWheel` (`Sources/ScrollWheel/ScrollTransform.swift`) без зависимостей от системы: по дельтам двух осей,
  `isContinuous` и фазам возвращает новые дельты или nil (не трогать). Не трогаем: continuous (тачпад, Magic Mouse),
  события с `scrollPhase`/`momentumPhase`, и всё, если обе функции выключены. «По строкам»: направление по первому ненулевому полю
  (FixedPt → строки → точки; при медленной прокрутке строк бывает 0, а дробь нет), дальше `n` строк, `n.0` fixed, `n × 10` точек.
  Обращение: смена знака всех трёх полей после «по строкам» (без «по строкам» обращаются системные значения с ускорением).
- `MouseScroller.swift`: активный tap (`.defaultTap`) только на `scrollWheel`, «Универсальный доступ». Пока обе функции выключены,
  tap не создаётся. Событие меняется на месте, ничего не глотается.
- Модуль «Мышь»: «Обратить прокрутку колеса», «Прокрутка по строкам, без ускорения», «Строк за щелчок колеса» 1–10 (по умолчанию 3),
  состояние, текущее значение «естественной» прокрутки (`com.apple.swipescrolldirection`), статус разрешения с кнопками,
  предупреждение, если запущен LinearMouse (`com.lujjjh.LinearMouse`, его не завершаем). Настройки — в `AppSettings`
  (`reverseWheel`, `linearWheel`, `wheelLines`), перехват включается при запуске приложения и работает с закрытым окном.

**Поля события (проверено на macOS 27.2 синтетическими событиями, без отправки в систему).**
- `CGEvent(scrollWheelEvent2Source:units:.line, wheel1: n)` даёт `DeltaAxis = n`, `FixedPt = n.0`, `PointDelta = 10·n`,
  continuous 0 — отсюда 10 точек на строку.
- Запись `DeltaAxis1` сама пересчитывает `FixedPt` и `PointDelta` (5 строк → fixed 5.0, point 40 — по своей таблице, не ×10).
  Поэтому порядок записи: строки → fixed → точки, иначе точки будут не наши.
- Shift + колесо приходит как Axis1 с флагом Shift, горизонталью его делает приложение (AppKit, браузер), поэтому
  Axis1 преобразуется так же. Наклон колеса — Axis2, обрабатывается тем же кодом. Обращение действует на обе оси.
- Кто какое поле читает: AppKit (Finder, Xcode, Telegram, Safari через NSEvent) — `FixedPt` как `deltaY` для неточной прокрутки
  и умножает на высоту строки своего вида; Chrome — тоже `deltaY` из NSEvent (≈40 px на единицу). `PointDelta` идёт в
  `scrollingDeltaY` для точных событий. Согласованная запись всех трёх полей нужна, чтобы ни одно приложение не взяло старое значение.

**Проверено.** `swift test` — 18/18 (9 новых `ScrollWheelTests`: колесо вниз с обращением, обращение сохраняет ускоренные
значения, тачпад/фазы/инерция не меняются, при выключенных функциях nil, фиксированные 3 строки при входных 1/9/0.1/−12,
1/5/10 строк, обращение вместе с «по строкам», наклон колеса, Shift + колесо). `./build.sh --install` без ошибок и
предупреждений, подпись «Mac Tweaks Dev». Запуск: раздел «Мышь» открывается, «Универсальный доступ — не разрешён»,
предупреждение про LinearMouse показывается (он запущен). «Клавиатура» после переноса на общий tap: «разрешён», «работает».

**Не проверено (нужен пользователь с мышью).** Живая прокрутка с выданным «Универсальным доступом» и закрытым LinearMouse:
направление и число строк в Safari, Chrome, Finder, Xcode, Telegram; Shift + колесо; что тачпад не изменился.
Результат по приложениям — дописать сюда. Возможный риск: обработчик работает в главном потоке приложения; если главный поток
надолго занят, система отключит tap по таймауту (мы его включим обратно) — на практике в Mac Tweaks главный поток простаивает.

## 2026-11-03 — Клавиатура: смена языка по Command+Shift (ветка `feature/keyboard`)

**Задача.** Повторить CommandShift.app (`vasybaran.loveFromUkraine.CommandShift`): нажали и отпустили Cmd+Shift без других клавиш — следующая раскладка.

  каждая должна быть зажата хотя бы одной, лишних модификаторов нет) и автомат `ModifierTapDetector`. Срабатывает, когда
  отпущены все модификаторы, если сочетание было набрано целиком и между ними не было другой клавиши или клика.
  Порядок нажатия/отпускания и сторона (левый/правый) не важны. Новые сочетания (правый Cmd и т.п.) — новый кейс
  `LayoutHotkey` с аккордом; `ModifierChord.rightCommand` уже есть и покрыт тестом. Caps Lock — состояние, а не зажатая

- Тесты `Tests/KeyChordTests` (`swift test`, 9 тестов, все проходят): Cmd↓Shift↓Shift↑Cmd↑ → да; Shift↓Cmd↓Cmd↑Shift↑ → да;

  Cmd+Shift+Option и Ctrl+Cmd+Shift → нет; набор текста до сочетания не мешает; состояние сбрасывается между нажатиями.
- `LayoutSwitcher.swift`: listen-only `CGEvent.tapCreate` (session tap) на `flagsChanged`, `keyDown` и нажатия кнопок мыши,
  в главном run loop — работает и с закрытым окном. Стороны модификаторов — по битам `NX_DEVICE*KEYMASK`; если их нет
  (синтетическое событие), считается левая. Caps Lock в наборе не учитывается, иначе при включённом Caps сочетание не сработало бы.
  `tapDisabledByTimeout/UserInput` → tap включается заново. Пока функция включена, раз в 2 с проверяется разрешение:
  выдали — tap создаётся без перезапуска приложения, отозвали — tap снимается.
- Разрешение — «Мониторинг ввода» (`CGPreflightListenEventAccess`), для listen-only его достаточно, «Универсальный доступ» не нужен.
  Запрос (`CGRequestListenEventAccess`) — только по кнопке «Запросить доступ».
- Переключение: `TISCreateInputSourceList` (категория keyboard, select-capable, только включённые), исключены родители методов
  ввода с режимами (`kTISTypeKeyboardInputMethodModeEnabled`) — выбираются сами режимы; следующая по кругу после текущей,
  `TISSelectInputSource`. Список и текущая раскладка в модуле обновляются по `kTISNotify…Changed`.
- Модуль «Клавиатура»: переключатель «Command+Shift меняет язык» (в `AppSettings.layoutHotkey`, по умолчанию выкл), состояние,
  статус разрешения с кнопками, список раскладок с отметкой текущей, предупреждение, если запущен CommandShift
  (по bundle id или имени, обновляется по запуску/завершению приложений). CommandShift не завершаем.

**Выбор способа переключения.** `TISSelectInputSource`: на macOS 27.2 проверил отдельной утилитой — RussianWin ↔ U.S. по кругу
4 раза, статус 0, `TISCopyCurrentKeyboardInputSource` каждый раз показывает выбранную. Эмуляция «Выбрать следующий источник
ввода» (символьный хоткей 61, у пользователя ⌃⌥Space) не нужна: она требует «Универсальный доступ» для отправки событий

## 2026-11-03 — Dock: узкий пробел появлялся только со второго клика

**Проверка пользователя.** Обычный пробел добавляется сразу. Узкий: после первого клика Dock перезапускается,
но пробела нет; после второго появляется.

**Причина (гипотеза, по описанию).** Скорее всего, дело не в типе пробела, а в порядке действий: первым нажимали обычный.
`killall Dock` посылает SIGTERM, и Dock перед выходом сохраняет свой список значков из памяти. Если в нём есть
несохранённые изменения (например, только что перетащили пробел), он затирает нашу запись в `persistent-apps`.
При втором клике Dock только что перезапущен, затирать нечего, и запись сохраняется. В настройках на момент разбора
было 47 плиток, как в резервной копии: добавленные в тесте пробелы оттуда пропали, историю по ним восстановить нельзя.

**Что сделано.** После записи приложение ждёт, пока launchd запустит новый процесс Dock (новый PID, до 5 с, плюс 0,8 с),
перечитывает настройки и, если изменения нет, вносит его ещё раз и перезапускает Dock повторно. Так же для «Убрать все пробелы».
В статусе пишется, что понадобился повтор. Пока идёт перезапуск, кнопки заблокированы. Восстановление из копии пока без такой проверки.

**Проверено пользователем на macOS 27.2.** После исправления обычные и узкие пробелы добавляются с первого клика,
всё работает. Пробелы в правой части Dock (`persistent-others`, у папок и корзины) на macOS 27.2 работают.
«Восстановить из последней копии» (`defaults import` + `killall Dock`) работает.

## 2026-11-03 — Старт проекта, модуль «Строка меню»

**Задача.** После обновления до macOS 27.2 отступы между значками в строке меню стали неровными:
у одних значков уже, у правых (системных) — шире. Раньше отступы задавались вручную через `defaults`.

**Что было в системе.**
- `defaults read -globalDomain`: `NSStatusItemSpacing = 5`, `NSStatusItemSelectionPadding = 3`.
- На уровне `-currentHost` этих ключей не было.
- Значки справа рисует `ControlCenter`, часть системных — `SystemUIServer`.

**Гипотеза (не проверена).** На macOS 27 ControlCenter читает отступы иначе,
чем приложения. Плюс сторонние приложения подхватывают отступы только при своём запуске.

**Что сделано.**
- Swift Package + SwiftUI, сборка `build.sh` → `dist/MacTweaks.app`, установка в `~/Applications`.
- Модуль «Строка меню»: ползунки интервала и подсветки, пресеты (2/2, 6/4, 10/8), предпросмотр.
- «Применить» пишет ключи в оба уровня (any и currentHost) и перезапускает `ControlCenter` и `SystemUIServer`.
- «Сбросить к системным» удаляет ключи на обоих уровнях.
- Перезапуск сторонних приложений строки меню (агенты из `/Applications`) с подтверждением; кнопка выхода из системы.

**Что не проверено.**
- Выравниваются ли системные значки после перезапуска ControlCenter на macOS 27 — пользователь ещё не применял.
- Значения по умолчанию (16/16) в коде взяты по памяти, на macOS 27 не сверены.
- Внешний вид окна не проверен скриншотом (`screencapture -l` не нашёл окно).

**Дальше.** Пользователь пробует «Компактно» → «Применить» → перезапуск приложений → при необходимости выход из системы. Результат записать сюда.
